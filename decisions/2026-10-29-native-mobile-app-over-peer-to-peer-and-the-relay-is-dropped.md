## 2026-10-29 · The relay and web companion are dropped; the native mobile app will reach desktops peer to peer

Supersedes [2026-10-29-web-companion-tunnels-to-the-desktop-app-through-a-relay](2026-10-29-web-companion-tunnels-to-the-desktop-app-through-a-relay.md) and [2026-10-29-the-relay-ships-as-a-self-hosted-docker-image](2026-10-29-the-relay-ships-as-a-self-hosted-docker-image.md), and moves the PWA from [2026-10-29-mobile-app-and-web-companion-are-pwas-on-the-hosted-server](2026-10-29-mobile-app-and-web-companion-are-pwas-on-the-hosted-server.md).

A relay that can read and drive every connected desktop is not something to offer anyone else, and a self-hosted one is more infrastructure than a person with one desktop should need. Removed: `web-companion/` (client, relay, Docker image) and the desktop's `Tunnel` and its "Browser companion" settings. Kept because they stand on their own: `src/core/dispatch.ts` and `src/shared/clientSide.ts` (shared by the hosted server and whatever serves a desktop), `hosted/src/static.ts`, and `hosted/src/push.ts` (its per-user resolver is now unused).

The browser PWA for one hosted server is `hosted/pwa` (was `mobile-app/`; the shared worker is now `hosted/web/worker/`). `mobile-app/` at the root is for a native app (Capacitor) that holds several instances: hosted ones by URL and token, desktops peer to peer. The peer-to-peer design copies the approach of the user's game-server project: no coordinating server; the host opens one UDP port and shares a code of every address it can be reached at (router forward if switched on, STUN, local, IPv6 and VPN addresses); the joiner probes them all and the first reply wins. Unlike that project, helm's channel must be encrypted and authenticated (the code carries the host's key and a one-time secret; unauthenticated packets get no reply), and UPnP is off by default. The protocol is written once in TypeScript over a `UdpSocket` interface. Notifications with the app closed need a push path that is still undecided.

Why: user request. The p2p project cannot be ported, so its mechanisms are being lifted from its description, with the user relaying questions to it.
