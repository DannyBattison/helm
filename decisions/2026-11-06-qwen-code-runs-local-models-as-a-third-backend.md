## 2026-11-06 · Qwen Code runs local models as a third backend, off until turned on
`src/core/qwenBackend.ts` runs `qwen --acp` (one process per session) against Ollama's OpenAI-compatible API, speaking ACP directly rather than through a shared AcpBackend. It has its own tab under Accounts: server status and start, server address, context size, installed models, and one-click download of recommended ones. `AgentBackend.setupNeeded()` lets an agent say what is missing beyond a sign-in, so it counts as ready only with the CLI, a running server and a model. Helm makes a copy of each model with the chosen context size (`<model>-helm32k`) because Ollama's default silently truncates agent prompts, and hides those copies from the model list. It is not in `enabledAgents` by default. No cost, plan, subagents, effort or fork; instructions go at the start of the first message because ACP has no field for them. Tested against a stand-in ACP agent and a stub Ollama; never run against real Qwen Code or Ollama, so the `--acp` flag, the `authenticate` method choice, `session/set_mode` ids and `/api/create` parameters are from documentation and unverified (`spike/qwen/README.md`).
Why: user asked to build the free, unlimited, local agent beside Claude and Codex. Follows `2026-11-06-free-means-local-and-unlimited-not-hosted-free-tiers`. A generic AcpBackend can be extracted when a second ACP agent (Cursor) is added.
