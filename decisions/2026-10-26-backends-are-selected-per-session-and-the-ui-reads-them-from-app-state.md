## 2026-10-26 · Backends are chosen per session, and the interface reads models and capabilities from app state
Nothing outside `src/core/claudeBackend.ts` talks to the Claude Agent SDK any more. `AgentBackend` also covers conversations (info, rename, fork, subagent and external transcripts, live sessions), plan usage, sign-in and the installed version. A `BackendRegistry` holds the backends; each session records its `backend` (empty means the first, for sessions saved before there were others) and `Settings.defaultBackend` picks the one for new sessions. `ModelAlias` is now just a model id string, and each backend lists its models and prices. `AppState.backends` gives the UI each backend's models, capabilities and version, and the model pickers, the effort and plan-mode controls and the fork buttons come from it. A second agent is a new `AgentBackend` registered in `core.ts`. Renamed: `claudeSessionId` → `agentSessionId` (migrated on load), `claudeLogin*` API → `agentLogin*` (taking a backend id), `checkClaude` → `checkAgent`, `AppState.claudeVersion` → `backends[].version`. Still Claude's: the `claudePath` setting, the `.claude` memory/CLAUDE.md feature, and tool names in transcripts.
Why: user request, so Claude is one backend among others and the interface is the standard for every agent.
