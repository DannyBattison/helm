## 2026-10-26 · One-click conflict resolution, and forecasts that merge for real
The conflict forecast now snapshots each session's worktree (uncommitted and untracked work included, via a temporary index, moving no branch) and runs `git merge-tree` on those snapshots, against each other and against the base. Two sessions editing the same file are no longer flagged unless git says the edits actually clash; the file-name "overlap" is only the fallback when git is too old for `merge-tree --write-tree`. Each real conflict gets a Resolve button (Overview notice and session header) that sends the agent a prompt to merge the other branch (or `origin/<base>`), resolve every conflict keeping both sides' intent, test and commit.
Why: user request. Overlap warnings for non-clashing edits were noise; resolution is delegated to the agent because it knows the intent of its own changes.
