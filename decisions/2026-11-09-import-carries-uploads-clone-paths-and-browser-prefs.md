## 2026-11-09 · Import carries session uploads, remaps clone paths and restores browser layout choices
Audit of import/export for a server move found three gaps. (1) `uploads/` (files attached to a session) was not exported, and imported sessions kept the old machine's `uploads.dir`; it is now exported, and import points `uploads.dir` at this machine's copy (or drops it if the files are absent). (2) Imported repositories kept the old `localPath`, which fails with a missing folder; if the path is not on this machine the repo gets `<cloneRoot>/<owner>/<name>` as sync does, and is cloned when first needed. (3) Layout choices live in the browser's `localStorage` (`helm-*` keys: sizes, overview layout and range, filters), which a new server's origin starts without; the Settings page now sends them with the export (`client`) and writes them back on import, leaving out `helm-route` and the crash-loop guard keys.
Still not carried, by design: sign-ins and passwords (`*.bin`), Claude Code's own files under `~/.claude` (memory, CLAUDE.md, resumable agent history), uncommitted or unpushed work in worktrees (sessions arrive `worktreeGone`; use sync's Branches/Worktrees first), managed agent installs (`tools/`), caches, push subscriptions and machine settings.
Why: user is moving servers and wants no difference in what they see.
