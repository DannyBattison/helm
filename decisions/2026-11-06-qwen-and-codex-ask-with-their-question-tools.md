## 2026-11-06 · Qwen and Codex ask questions with their own question tools, shown as helm's question prompt
Both agents were only told to "ask the user", so they asked in a plain message the user then had to answer in free text. `AgentBackend.askTool` now names each agent's question tool and the session instructions say to use it (`AskUserQuestion` for Claude, `ask_user_question` for Qwen, `request_user_input` for Codex). Qwen delivers a question as a `session/request_permission` flagged `qwenInteractionKind: user_question`; helm shows it through `AskUserQuestion` and replies with Submit and `answers` keyed by question number (multiple choices joined with commas), or Cancel if the user declines. Checked against the real Qwen Code: the answers come back as the tool result. Codex already had the mapping from `item/tool/requestUserInput`, but its tool is only offered in plan mode unless the feature `default_mode_request_user_input` is on, so helm sets it in the thread config (the flag is "under development" in Codex 0.167, and the config is accepted by the real app server; whether a model then calls the tool was not observed, since that needs a signed-in Codex). A small model may still write a question as text instead of calling the tool.
Why: user asked for questions to work like Claude Code's, for Qwen and Codex.
