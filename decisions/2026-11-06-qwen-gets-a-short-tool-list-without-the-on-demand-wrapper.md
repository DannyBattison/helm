## 2026-11-06 · Qwen gets a short tool list with no on-demand wrapper
Offering web fetch directly (`tools.visible`) did not stop a small model calling Qwen Code's `tool_call` wrapper, which was still in its tool list, so the same "ToolCall failed" cards came back. Helm's own Qwen settings file now excludes `tool_call` and `tool_search`, which makes Qwen offer its tools directly, and also the helper, worktree, scheduling and similar tools a small model only gets lost in. Checked with the real Qwen Code: the model is offered nine tools (files, search, shell, web fetch, ask-the-user, image zoom) and no wrapper. The settings file is written when a Qwen process starts, so a session that is already running keeps the old list until it is started again. The exclude list names tools by hand, so a Qwen release that adds tools will offer them until the list is extended. Supersedes the `tools.visible` part of `2026-11-06-qwen-tools-shown-by-arguments-and-web-fetch-offered-directly`.
Why: the user's second run still failed the same way.
