## D-134 · 2026-10-26 · Automated agents start sessions on a schedule or when something happens on GitHub
An automated agent is a saved prompt with a trigger, global (every repository) or for one repository. Triggers: a schedule (hourly, daily, weekdays or weekly at a local time), a pull request opened, a pull request merged, an issue opened. Each firing starts an ordinary session (`Session.automation` records which agent), so it shows in the list, uses the queue and `maxRunning`, and asks for approval as set on the agent. helm has no server for GitHub to call, so events are found by polling every minute (pull requests and issues via the GitHub API, only for repositories with an enabled event agent): the first look at a repository only records what exists, so old pull requests do not fire. A schedule that was missed while helm was closed fires once when it next runs; editing a trigger restarts the count. A pull request session is based on the pull request's branch; other sessions on the default branch. Pull requests from branches of sessions that automated agents started never fire event agents (so a review agent cannot trigger itself), and one agent starts at most 5 sessions per repository per poll. A global schedule starts one session in every repository: mind the cost. Prompts may use `{{repo}}`, `{{number}}`, `{{title}}`, `{{url}}`, `{{branch}}`. Agents live in `helm.json` (`automations`, `automationSeen`).
Why: user request.
