## 2026-10-26 · Codex is a second backend, driven through `codex app-server`
`CodexBackend` talks to one shared `codex app-server` process (JSON lines over stdio); each session is a Codex thread. Codex's items are translated into Claude Code's tool vocabulary so the rest of helm is unchanged: command executions become `Bash`, file changes become `Edit`/`Write` built from the unified diff, MCP calls keep their names. Approvals and questions go through `canUseTool`. Fork-from-a-message uses `thread/fork` with `lastTurnId`. Models come from `model/list`, plan windows from the account's rate-limit snapshot (the five-hour and weekly windows told apart by length), sign-in is the device-code flow (`chatgptDeviceCode`) and an `OPENAI_API_KEY`/`CODEX_API_KEY` in the environment signs it in. Not done: Codex's subagents are shown as a single tool call and are not limited by helm; it reports tokens but no dollars, so dollar budgets do not trigger for Codex (its price is zero); the CLAUDE.md "remember" button is hidden for Codex sessions (it reads AGENTS.md); the desktop app does not bundle Codex, so it must be on the PATH or set under Settings → Agents; permission modes map to Codex's approval policy and sandbox (ask → untrusted + workspace-write, edits → on-request + workspace-write, plan → read-only, all → never + full access).
Why: user request, chosen over a generic ACP backend because only two agents are needed and the native protocol keeps fork-at-a-turn, rate limits and structured sign-in.
