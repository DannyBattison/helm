## 2026-10-28 · Repository settings override the defaults; repositories can be hidden
Repositories get a `settings` record of overrides (`shared/repoSettings.ts` lists the keys: agent and model, effort, permissions, session limit, standing instructions, tests, branch prefix, fetch, copied files, commit and push behaviour, delivery, merge and after-merge). Whatever a repository leaves out follows the global value, so changing a default reaches every repository that has not overridden it. Core reads `effectiveSettings(global, repo)` wherever a session's repository matters. Settings has a root "Defaults" screen for the global values and a "Repositories" group with one screen per repository; the repository view has a Settings tab with the same screen. Machine-wide settings (paths, appearance, budgets across repositories) are not overridable, and neither are the "remove worktree/branch after merge" options, which are copied onto each session when it is made.

A repository can also be hidden (`Repo.hidden`). Hidden repositories leave the sidebar, quick jump, the command palette, the new session dialog and the dashboard, but keep all data, stay listed in Settings (marked hidden) and can be shown again there or from the repository's Settings tab. Hiding is refused while the repository has sessions that are not archived. Archived sessions of a hidden repository remain in the Archive.
Why: user request.
