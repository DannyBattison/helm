## 2026-10-29 · The desktop can ask the router to forward its port (UPnP, then NAT-PMP); a tapped notification opens its session

**Port forwarding** (`src/core/p2p/portmap.ts`, Settings → Phone app → "Open the port on my router", off by default because it changes the router). UPnP first: SSDP M-SEARCH from each private IPv4 address, the device description, the WAN connection service, then SOAP `GetExternalIPAddress`, `AddPortMapping`, `GetSpecificPortMappingEntry` (read back; "OK" alone is not trusted), `DeletePortMapping`. NAT-PMP if there is no UPnP (default gateway found per platform; external-address and map requests). Both written out with no libraries, as in the user's game project. Differences from that project's, which has no lease renewal and leaves permanent mappings after a crash: the lease is an hour and is renewed at half of it (also re-creating a mapping a rebooted router forgot); only a router that refuses leases (error 725) gets a permanent one; the mapping is deleted on quit, awaited in `shutdown()`; a taken external port (718) moves to the next few. A router that reports a private or carrier-grade address is behind another NAT and the mapping is removed rather than advertised. The mapped address goes first in the share code. Tested against a fake router (SSDP, HTTP/SOAP, NAT-PMP) on loopback; never against a real router.

**Notification taps** (`mobile-app/src/open.ts`): the notice carries the instance id and session; Android's background notification uses a `helm://open` link the manifest handles (read with Capacitor's App plugin, also for a cold start), iOS puts the fields in `userInfo`, which Capacitor's local-notifications plugin reports as `extra`, and in-app notifications set the same extra. Same computer already open: go to the session; another: reload into that one (target kept in `sessionStorage`) and go; removed: ignore. The native Java and Swift changes are uncompiled like the rest.

Also pinned Node 22 (`.nvmrc`, `engines`) after the Mac build failed on an old Node (`node:util` `styleText`).

Why: user request.
