## 2026-10-29 · The web companion tunnels to the desktop app through a relay, paired by GitHub and a code

Supersedes the part of [2026-10-29-mobile-app-and-web-companion-are-pwas-on-the-hosted-server](2026-10-29-mobile-app-and-web-companion-are-pwas-on-the-hosted-server.md) that served the web companion from hosted helm. The web companion now reaches the user's desktop app, not a server's core.

A desktop app is behind NAT, so both sides connect out to a relay (`web-companion/relay/`, run by the user behind TLS). The desktop (`src/core/tunnel.ts`, Settings → Browser companion, off by default) connects with its GitHub username, a secret id and a generated code (`XXXX-XXXX`, 31-letter alphabet without lookalikes, single use, rotated every 10 minutes and after each use). A browser signs in to the relay with GitHub's device flow (no scope: the relay learns a username and keeps no token) and types the code. The relay joins a browser only to a desktop signed in as the same username with the current code, rate limits guesses, and gives the browser a signed pairing cookie naming that desktop's id. Revoking in the desktop settings makes a new id, which ends every pairing.

The relay forwards the same `call`/`result`/`event` protocol hosted helm speaks, so the browser runs the unchanged renderer through the shared `boot()`, and the desktop runs calls through the same `dispatch` as the hosted server (moved to `src/core/dispatch.ts`, with `CLIENT_SIDE` in `src/shared/clientSide.ts`). A paired browser can do whatever the window can except what acts on the desktop computer. Notifications go to the relay even with no browser open and become Web Push there, one store per user, so they reach a closed page; this reuses `hosted/src/push.ts`. The old "Companion" setting (a different, separate-repository server with snapshots) is untouched.

Why: user request. The relay can see the traffic, which is why it is self-hosted; end-to-end encryption between browser and desktop would remove that and is not done. Not done: honouring "Let the website control agents" for the tunnel (a paired browser has full control), and a desktop-side list of paired browsers.
