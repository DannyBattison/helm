## 2026-10-29 · The phone app reaches a desktop over an encrypted UDP link, paired by a code and the same GitHub user

Implements the direction in [2026-10-29-native-mobile-app-over-peer-to-peer-and-the-relay-is-dropped](2026-10-29-native-mobile-app-over-peer-to-peer-and-the-relay-is-dropped.md), taking the mechanisms of the user's game-server project (one UDP port; share code of candidate addresses; STUN on the same socket every 25 s; probe all addresses, first reply wins; no coordinator) and changing what helm needs:

- **Encrypted and authenticated** (`src/shared/p2p/noise.ts`, `link.ts`): Noise IK (X25519, ChaCha20-Poly1305, BLAKE2s) over `@noble` libraries. The first handshake message is the probe; a host answers only a first message from a device it accepts, so the port shows nothing to a scan or a replay. Keys, not addresses, identify a link, so it follows a phone across networks. Hand-written Noise: it needs an independent review before anyone relies on it.
- **Pairing** is a share code (`HELM1-` + base64url JSON: name, port, candidate addresses, the desktop's key, a one-time secret) plus a GitHub check: the phone signs in to GitHub with the device flow (no scopes) and sends the token, encrypted, in its first message; the desktop asks GitHub whose it is, requires it to be the GitHub user signed in on the desktop, and discards it. A known device is recognised by its key afterwards, and stops being recognised if a different user signs in on the desktop. A code is good for ten minutes and one device; a refused attempt does not spend it.
- **Reliable stream** (`reliable.ts`): written new instead of lifting the game project's, which has no congestion control and was built for small exchanges; helm sends transcripts and diffs. Selective acks, RTT-based timers, slow start and additive increase, loss detection by count and by time; tested under 20% loss with reordering and duplication.
- **Addresses** (`src/core/p2p/addresses.ts`) ranked as the game project does (LAN, global IPv6, public IPv4, VPN, unique-local, virtual adapters last); a second STUN server classifies the NAT (symmetric means direct connection will not work). UPnP/NAT-PMP is not done: the port is settable for a manual forward, and the game project's code has no lease renewal anyway.
- **One connection layer** for every client: `createConnectionBridge` in `hosted/web/bridge.ts` (reconnect, queueing, state refresh) takes any transport, WebSocket for hosted servers or the UDP link for desktops. The desktop runs a phone's calls through the same `dispatch` as the hosted server, minus the calls that act on the computer.

Stale codes: connected phones are sent the new addresses when they change and keep them; a phone that was away for an address change needs a new code, or a fixed address (dynamic DNS) in the code. Nothing reaches a phone with the app closed (no push path chosen yet), and the native shell and UDP plugin are not written or run on a phone.

Why: user request.
