## 2026-11-06 · Qwen tool cards wait for their arguments, and web fetch is offered to the model directly
First real run of the Qwen backend (qwen3:8b) showed three failed "ToolCall" cards. Driving the real Qwen Code against a scripted model server reproduced it: Qwen keeps some tools on demand (web fetch among them) behind `tool_search` and a `tool_call` wrapper, and a small model calls the wrapper with no arguments (`params must have required property 'name'`). Fixes: helm writes a settings file of its own (`<data dir>/qwen-settings.json`, `tools.visible` listing `web_fetch`, `web_search`, `todo_write`) and passes it with `QWEN_CODE_SYSTEM_SETTINGS_PATH`, so the model sees those tools directly and the user's Qwen settings are untouched; the wrapper is shown as the tool it calls when it does work; a tool's card now waits until Qwen has sent its arguments (it announces a call first with an empty input), so it reads `echo hi`, not "Shell"; and tokens are reported per model call from `_meta.usage` as they arrive, not only at the end of a turn (a turn stuck retrying showed 0 tokens). An 8B model is still weak at agent work; that is the model, not helm.
Why: user's first real Qwen session. Fixes the assumptions in `2026-11-06-qwen-code-runs-local-models-as-a-third-backend`.
