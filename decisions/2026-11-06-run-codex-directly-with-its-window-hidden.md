## 2026-11-06 · Codex is run as its native binary with its window hidden, to stop a terminal popping up on Windows
After Codex was installed on Windows, a terminal window opened whenever helm ran and came back each time it was closed. Helm started `codex app-server` without hiding its window, and npm's `codex.js` launcher then starts the real `codex.exe` with an inherited console; an app with no console of its own gets a new terminal for that. Closing it killed Codex, and helm started it again on its next request. Helm now spawns every Codex and Qwen process with `windowsHide`, only uses a shell for `.cmd` and `.bat` files, and resolves npm's launcher script (`@openai/codex/bin/codex.js`, which is what the one-click install and already-saved settings point at) to the native binary in the platform package, so there is no launcher to open a console. Qwen Code is plain JavaScript, so it had no such launcher, but its processes are hidden too. Tested for the path mapping and against the real package layout on Linux; the Windows window itself was not observed. A tool Qwen or Codex starts for its own shell commands may still behave differently on Windows.
Why: user report.
