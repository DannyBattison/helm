## 2026-10-27 · Codex has subagents and its own memory; both agents' plan limits show together
Correction to the Codex entry: Codex does support subagents (its models declare a multi-agent runtime and it starts helpers with a `spawnAgent` call). helm now shows each helper as a subagent, keeps it working until the helper's thread ends, and reads its transcript from that thread. helm's per-session subagent limit is passed to Codex as `agents.max_concurrent_threads_per_session` (limit + 1, since the session counts as a thread); the repository-wide limit cannot be applied to Codex. Both settings are read from the Codex binary's strings and its protocol types, and have not been run against a signed-in Codex. Memory: the repository's Memory tab has a Claude Code / Codex switch. Codex shows AGENTS.md, AGENTS.override.md, `~/.codex/AGENTS.md` and the notes in `~/.codex/memories` (CODEX_HOME), which are edited but not deleted, since Codex also keeps them in a database; Remember on a message writes to AGENTS.md for a Codex session. The sidebar's usage area and the overview's weekly figure show every agent paid by a plan. An agent that ships with helm (Claude) stays usable when its sign-in could not be checked.
