## 2026-10-26 · ACP is viable as the way to add other agents; Claude stays on its native backend
A spike (`spike/acp/`) drove `claude-agent-acp` for real and started `codex-acp`. ACP covers streamed output, tool calls with diffs, approvals, cancel, cost and context (`usage_update`), session resume/load and listing, and titles, which is most of `AgentBackend`. It does not cover plan-usage windows, a pre-start gate for subagents, fork-from-message, or choosing a model or effort, and shell commands arrive in later updates rather than on the first tool call. So a generic `AcpBackend` would run Codex, Gemini and others with those capabilities switched off, and Claude keeps its native SDK backend for subagent limits, plan meters and forking. Codex itself was not run past `initialize` (no credentials), so its behaviour is read from its source.
Why: user request, to check the unknowns before committing to ACP.
