## 2026-10-28 · Repository files copy in the background; zips unpack; folders can be shared read-only

Copying a repository's uploaded files into a new worktree made creating a session slow. The session is now created at once (transcript opens) with `preparing` progress while the copy runs; the agent starts when it finishes, and `start` waits on any copy still in flight. Copies go to a temporary name and are renamed so a cut-short copy is never mistaken for complete. A `.zip` can be unpacked into a folder of the same name (structure kept; entries climbing out of the folder are refused and macOS junk skipped). Any file or folder can be marked shared: worktrees get a symlink and the stored copy is made read-only, so nothing is copied and no disk is used. Worktrees that already hold a copy keep it.
