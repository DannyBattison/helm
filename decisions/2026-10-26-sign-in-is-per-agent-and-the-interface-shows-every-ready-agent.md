## 2026-10-26 · Sign-in is per agent, and the interface shows every agent that is ready
On the hosted server the first screen asks for a sign-in to Claude or ChatGPT; one is enough, and the other (and signing out of either) is under Settings → Agents, which also holds each agent's command-line path and account. The same rows work on the desktop, where the agent may already be signed in through its own CLI. `AppState.backends` carries each agent's models, capabilities, version, `installed`, `login` and `ready` (signed in and installed). The new-session dialog, compare runs, automations and the default-model setting list the models of every ready agent in one list (`agent/model`); inside a session the picker offers only that session's agent, since a conversation cannot move between agents. Plan limits are kept per agent (`AppState.plans`, `Store.planOf`), enforced per agent against the same pause percentages, and shown in the sidebar: the familiar two meters for one agent, two thin bars each when several. Billing is per agent too: Claude's is still the user's setting, any other agent's is read from its account. Agent names, commit identity (`Agent only` commits) and the question and subagent lines of the prompt follow the session's agent.
Why: user request, so either service can be used without the other and nothing in the interface assumes Claude.
