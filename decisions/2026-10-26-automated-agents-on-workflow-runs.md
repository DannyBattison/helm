## 2026-10-26 · Automated agents can start when a GitHub Actions run succeeds or fails
Two new triggers for automated agents: "When a GitHub Actions run succeeds" and "When a GitHub Actions run fails" (failure includes timed out and startup failure; cancelled and skipped runs start nothing). They use the same polling as pull request triggers: each poll reads the repository's 30 latest finished runs (`/actions/runs?status=completed`), the first look only records run ids, and later new runs start a session from the run's branch (the default branch if that branch is gone). Runs on branches of sessions that automated agents started are skipped, so an agent whose fix fails CI does not start another agent. The prompt can use `{{title}}` (workflow and run title), `{{number}}` (run number), `{{url}}` and `{{branch}}`.
Why: user request, to have an agent react to CI results (for example to fix a red build).
